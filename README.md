# 異世界遺失物センター

異世界から転送ゲートで届く落とし物を鑑定し、直し、持ち主の世界へ返す――スマホ向けのインクリメンタル（放置）ゲームです。
Vite + TypeScript（フレームワークなし）で作られた PWA で、一度開けばオフラインでも遊べます。

---

## 起動方法（Windows）

必要なもの：[Node.js](https://nodejs.org/) 20 以上（LTS 推奨）

1. このフォルダで PowerShell（またはコマンドプロンプト）を開く
2. 依存パッケージを入れる（最初の1回だけ）

   ```bash
   npm install
   ```

3. 開発サーバーを起動する

   ```bash
   npm run dev
   ```

4. ブラウザで `http://localhost:5173/` を開く

### その他のコマンド

| コマンド | 内容 |
| --- | --- |
| `npm run build` | 型チェック＋本番用ビルド（`dist/` に出力。Service Worker もここで生成） |
| `npm run preview` | ビルド結果をローカルで確認（PWA・オフライン動作はこちらで確認） |
| `npm run sim` | バランス確認用シミュレーション（仮想プレイヤーで数週間を早回し） |

`npm run sim -- 5 120 quiet` のように「1日のチェック回数」「日数」を渡せます。`quiet` を付けると移転のタイミングだけを表示します。

## スマホでの確認方法（同じ Wi-Fi）

1. PC とスマホを同じ Wi-Fi につなぐ
2. PC で次のコマンドを実行する

   ```bash
   npm run dev -- --host
   ```

3. 表示された `Network: http://192.168.x.x:5173/` の URL をスマホのブラウザで開く
   - 開けないときは、Windows のファイアウォールで Node.js の「プライベート ネットワーク」の通信を許可してください（初回起動時に出るダイアログで「許可」を押せば OK）。
   - PC の IP アドレスは `ipconfig` の「IPv4 アドレス」でも確認できます。

### ホーム画面に追加して遊ぶ（PWA）

開発サーバー（`npm run dev`）では Service Worker は動きません。オフライン対応を確かめるときは本番ビルドを使います。

```bash
npm run build
```

```bash
npm run preview -- --host
```

スマホで表示された URL を開き、「ホーム画面に追加」すると単体アプリのように起動できます。
※ iPhone/Android ともに、Service Worker は本来 HTTPS（または localhost）でしか有効になりません。LAN の `http://192.168...` では画面確認はできますが、オフライン動作の確認は PC の `http://localhost:4173/` か、HTTPS で公開した環境（GitHub Pages、Netlify など。`dist/` をそのまま置けば動きます）で行ってください。

## 遊び方の流れ

**開館 → 回収 → 処理 → 仕込み → 閉館**

- **転送ゲート**：3時間ごとに落とし物が届く（量はゲートLv次第）。倉庫の上限は24時間分。入りきらない分はゲート前で待ち、消えません。
- **鑑定**：品物の手がかり（2〜3個）から、どの世界の品かを3択で当てる（正解で礼金×2）。鑑定士に任せれば1件約3分で自動。
- **修理**：破損品は、その世界の素材を使って工房で直す。
- **返却**：配達員を世界へ派遣（数時間）。帰還すると信用・礼金・素材と、持ち主からの手紙が届く。
- **閉館**：処理待ちが0で、配達員が全員出発していれば「本日閉館」。成果、留守中の予定、次に開くおすすめ時刻を表示します。
- 窓口の「次の一手」に、いまやるべきことが優先度順に最大3つ並びます。

段階的に解放される要素：職員（鑑定士・修理工・配達員／Lvと特性）、施設（倉庫・鑑定室・工房・ゲート）、研究（タイマー制）、図鑑（世界別の収集とセットボーナス）、持ち主の手紙、「探しています」の依頼、支所の移転（周回）。

- **放置**：最終処理時刻からの差分をまとめて計算します（上限24時間）。
- **保存**：localStorage に5秒ごと＋画面を離れたときに自動保存。右上の歯車から**エクスポート/インポート**（文字列またはファイル）ができます。

### バランスの目安（`npm run sim` の結果）

| 遊び方 | 移転1回目 | 全6回の移転 |
| --- | --- | --- |
| 1日6回チェック | 約8日 | — |
| 1日5回チェック | 約9日 | 約80日 |
| 1日4回チェック | 約10日 | — |

数値はすべて `src/core/balance.ts` と `src/data/research.json` に集まっています。

## フォルダ構成

```
src/
  core/         ゲームロジック（DOMに触れない純粋なTS。シミュレーションでも使う）
    types.ts      状態とデータの型
    data.ts       JSONの読み込み、データが無い世界の仮データ生成
    balance.ts    数値・計算式
    engine.ts     時間経過の処理（ゲート、作業、帰還、研究）
    actions.ts    プレイヤーの操作、閉館判定、「次の一手」
    save.ts       保存・読み込み・エクスポート
  ui/           画面（DOM）
    app.ts        全体の制御（毎秒の更新、タブ、トースト）
    screens/      窓口・倉庫・職員・地図・図鑑
    modals.ts     鑑定の3択、手紙、開館・閉館、設定など
    styles.css    見た目
  data/         ゲームデータ（JSON）
scripts/simulate.ts  バランス確認用シミュレーション
```

## データの追加方法

ゲームデータはすべて `src/data/*.json` にあります。保存して `npm run dev` のままなら自動で反映されます。
（**ID は一度公開したら変えないでください。** セーブデータが ID で品物・持ち主を記録しているためです。）

### 世界：`worlds.json`

```json
{
  "id": "w05", "name": "夜だけの街ノクタ", "short": "ノクタ",
  "color": "#2F3C78", "material": "月蝋", "travelHours": 5, "value": 135,
  "desc": "世界の説明文",
  "x": 110, "y": 420
}
```

- `color`：世界の識別色（荷札の帯・地図の点）
- `travelHours`：配達の往復時間の基本値、`value`：品物1件あたりの礼金・信用の基本値
- `x`,`y`：地図上の位置。線のつながりは `map.json` の `links` で決めます
- 世界の開通条件：最初の2つ＋研究（`research.json` の `"kind": "world"`）＋移転（`relocations.json`）

### 品物：`items.json`

```json
{ "id": "i0501", "world": "w05", "name": "畳み忘れた窓", "desc": "説明文", "clues": ["手がかり1", "手がかり2", "手がかり3"] }
```

- `clues` は2〜3個。ほかの世界と少し紛らわしいものを混ぜると、3択が面白くなります
- **ある世界の品物が1つも無い場合は、自動で仮の品物（6種）が使われます。** 1つでも書けば、その世界は書いた品物だけになります

### 持ち主と手紙：`owners.json`

世界IDごとに8人（何人でも可）。手紙は3通で、その持ち主の品を **1・3・6件目** に返したときに届きます。

```json
"w03": [
  { "id": "o0301", "name": "名前", "profile": "紹介文", "letters": ["1通目", "2通目", "3通目"] }
]
```

- 書いていない世界は「〇〇の住人・一番」などの仮の持ち主と定型の手紙になります
- 手紙の中で `{item}` と書くと「お届けの品」に置き換わります

### 「落とし主」の謎：`mystery.json`

全20段階。`req` を満たすと解放されます。

```json
{ "id": 6, "title": "ゼロ番", "req": { "letters": 32 }, "text": "本文" }
```

- `req` に使える条件：`letters`（受け取った手紙の数）、`relocations`（移転回数）、`worlds`（開通した世界の数）、`catalog`（図鑑の収集率 0〜1）
- `text` が `null` の段階は「まだ綴じられていない」と表示されます。続きを書くときは `text` を埋めるだけです

### そのほか

| ファイル | 内容 |
| --- | --- |
| `research.json` | 研究。`kind` は `world`（開通）/`flag`（自動化など）/`level`（段階強化。`stat` で効果の種類） |
| `staff.json` | 職員の名前候補と特性。特性の数値（`appraise`, `travel`, `cap` など）は `balance.ts` が読みます |
| `relocations.json` | 移転先、追加される世界、追加される仕組み（`mechanic`：`express`/`bulletin`/`bigcart`/`nightshift`/`hint`/`archive`） |
| `map.json` | 地図の線 |

新しい種類の仕組み（`mechanic`）や研究の `stat` を増やすときは、`src/core/balance.ts` に効果の計算を足してください。

## メモ

- フォントは BIZ UDPGothic と DM Mono を `@fontsource` で同梱しているので、オフラインでも表示が崩れません（初回のキャッシュは約6MB）。
- 設定の「動きを減らす」で、アニメーションを最小限にできます（端末の「視差効果を減らす」設定にも従います）。
- デバッグ用に、開発中はブラウザのコンソールから `__app.s` でゲームの状態を見られます。
